# ISS-001: Isolate AppState run-state and handler-state

## Description
`AppStateRuntime` still mixes event-loop run-state, handler reentrancy state, exit flags, stop flags, dispatch handler presence, and deferred callback draining. The deferred callback queue has a dedicated seam, but run-state and handler-state still require callers and tests to know too much about `app_state_runtime.val`.

## Design
Create a focused internal Module for AppState run-state/handler-state operations. Keep public behavior unchanged. Move mutation and queries for `is_running`, `event_handler_in_use`, `exit_requested`, `stop_*`, and dispatch handler readiness behind narrow functions. Avoid changing event ordering unless a regression test proves the current behavior is wrong.

## Acceptance Criteria
- [x] AppState dispatch code no longer directly mutates run-state/handler-state fields except through the new seam.
- [x] Existing AppState reentrancy and lifecycle white-box tests pass.
- [x] Add or update tests around handler clearing, exit, and stop flags if the seam changes observable internals.
- [x] `moon fmt`, `moon info`, and `scripts/check_ci.sh` pass.
