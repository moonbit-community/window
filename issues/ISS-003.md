## Description
Window request operations still map native status values, invalid handles, ignored operations, and `RequestError` payloads across multiple functions. The external API has structured errors, but the backend Implementation remains scattered.

## Design
Create an internal request/error handling Module for native window requests. Centralize status-to-`RequestError` mapping, invalid-handle policy, and common request wrappers. Keep source-level parity with winit non-goal; preserve usage habits and error semantics.

## Acceptance Criteria
- [x] Native window request status mapping lives behind one internal seam.
- [x] Cursor grab, cursor hittest, drag, and similar request paths share the same error conversion policy.
- [x] Existing structured `RequestError` tests pass or are strengthened.
- [x] `moon fmt`, `moon info`, and `scripts/check_ci.sh` pass.
