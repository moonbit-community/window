# ISS-004: Narrow borrowed raw AppKit handle usage

## Description
Owned native resources use external objects, but borrowed AppKit and Objective-C handles still flow broadly as `UInt64`. This is necessary at the raw FFI edge, but broad propagation makes the Interface ambiguous about borrowed, stable, retained, or callback-scoped handles.

## Design
Do not wrap every `UInt64`. Instead, identify high-value seams where raw borrowed handles enter public APIs or generic selector dispatch. Add narrow internal Adapters or helper Modules that document and concentrate borrowed-handle assumptions.

## Acceptance Criteria
- [x] Public raw-handle APIs remain documented as borrowed AppKit handles.
- [x] At least one high-traffic internal borrowed-handle path is narrowed behind an Adapter.
- [x] No owned native resource is represented as a plain `UInt64`.
- [x] `moon fmt`, `moon info`, and `scripts/check_ci.sh` pass.
